# Measurements

Lab baseline for plan epic E0.4. Generated by `node scripts/measure.mjs --md docs/MEASUREMENTS.md`; do not edit by hand, rerun the script.

- Measured: 2026-10-16 04:42 UTC, target local production build, checkout `bf38819`, Chrome/155.0.8059.80, viewport 1280x720, 2 run(s) per profile (median shown).
- Served: the production build (`ng build --stats-json`, service worker on) from a local static server on 127.0.0.1 with gzip and `max-age=600`, like GitHub Pages. Third-party data is fetched live from the internet, so third-party timings depend on the network at the time of the run.
- **Cold** = fresh Chrome profile, service workers blocked, HTTP cache disabled through CDP: a true first visit, onboarding modal on top.
- **Warm** = fresh Chrome profile with the service worker allowed; one priming load (onboarding dismissed, worker installed, IndexedDB filled), then a second load in a new tab is measured: the walkthrough's "warm revisit".
- Boot window: from navigation until the network is idle (nothing in flight and no request started or finished for 5 s), capped at 120 s. Requests and bytes are those started or received inside the window; downloads still running at the cap are counted as requests but only their bytes received so far. Lens, sidebar and route steps use the same rule with 3 s, capped at 45-60 s.
- JS heap is read from CDP after the boot window and once the main thread has had no long task for 3 s; the figure after a forced GC is the retained heap.
- api.github.com calls are counted when the request is issued, whatever GitHub answers; the unauthenticated limit is 60 per hour per IP, so repeated runs see 403s (status counts below).
